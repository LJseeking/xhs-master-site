# 小红书正文结构与爆款文风优化执行方案

## 1. 背景

当前正文生成链路同时受到以下内容影响：

- 一周计划生成的 `bodyStructure`
- 品类固定结构库中的主结构、可选开场和避免事项
- 爆款研究中的内容特征、人设启发和策略启发
- 各品类固定的事实与合规规则

其中，`bodyStructure` 和品类固定结构目前不仅决定写什么，还会影响开场方式、信息顺序和段落推进。即使系统已经提供爆款研究摘要，最终正文仍容易按照固定顺序展开，形成说明文、运营分析或高度同质化的表达。

本方案将“内容职责”和“文风职责”分离：

- `bodyStructure` 只提供无顺序、可省略的候选内容要点和事实范围。
- 爆款文风库决定叙述身份、开场方式、信息顺序、句式节奏、情绪浓度、口语程度和互动方式。
- 图片和账号真实资料决定可以写入正文的事实。
- 品类规则只负责真实性、合规性和不可伪造边界。

## 2. 优化目标

1. 避免正文机械按照固定顺序推进。
2. 避免不同帖子因为使用同一品类结构而形成相似表达。
3. 让正文文风能够明确参考真实爆款帖，而不是只读取宽泛的“内容特征”。
4. 爆款研究至少沉淀 5 种有明显差异的正文风格，每种至少有 2 个真实案例支撑。
5. 爆款增强策划案和 `AGENTS.md` 中能够完整保留文风特点、适用范围和案例。
6. 控制 OpenClaw 图片研究任务量，最多研究 30 张图片。

## 3. 不在本次范围内的事项

- 不修改图片方案的生成、编辑和发布流程。
- 不要求对历史爆款研究自动补造文风案例。
- 不要求修改 `bodyStructure` 数据库字段名。
- 不允许复制参考帖的完整正文、个人经历或未经核验的数据。
- 不使用品类固定结构作为正文文风兜底。

## 4. 字段职责重新定义

| 数据 | 新职责 |
| --- | --- |
| `topicTitle`、`coreView`、`contentGoal` | 确定本篇核心主题和写作目标 |
| `bodyStructure` | 提供无顺序、可省略的候选内容要点和事实范围 |
| 爆款文风库 | 决定叙述身份、开场、信息顺序、句式、段落节奏、情绪和互动方式 |
| 图片、账号资料、用户输入 | 提供实际可写事实 |
| 品类规则 | 提供真实性、合规性和不可伪造边界 |

### 4.1 `bodyStructure` 新语义

保留字段名以兼容现有服务端和历史数据，但将产品含义调整为：

> 本篇笔记的无序候选内容要点和事实范围。每项均可采用或省略，不代表正文顺序，也不要求逐项覆盖。

硬性规则：

- 不决定开场方式。
- 不决定正文信息顺序。
- 不决定段落数量和句子长短。
- 不决定第一人称或第三人称。
- 不决定情绪、口语程度和互动方式。
- 不要求全部候选要点进入正文。
- AI 可以根据图片、已知事实和所选文风省略任意不适合的候选项。
- 省略候选项不代表可以补造候选范围以外的事实。

## 5. 完整工作流

### 5.1 生成一周计划

一周计划 AI 继续返回 `bodyStructure` 字段，但输出内容改为无序候选项。

错误示例：

```text
开头点出主推菜 -> 讲适合人数 -> 补充搭配方式 -> 展示环境 -> 评论区提问
```

正确示例：

```text
可选内容要点：
- 主推菜的可见特点和口感
- 适合的用餐人数或聚餐场景
- 可以确认的搭配方式
- 图片中实际出现的门店环境
- 已确认的停车或预约信息
```

一周计划 Prompt 增加以下要求：

- 不使用“开头、接着、然后、最后”等顺序词。
- 不使用箭头或编号表达固定正文顺序。
- 只列与本篇主题相关的候选内容和事实范围。
- 每个候选项必须可以独立采用或省略。
- 不在 `bodyStructure` 中描述语气、文风、开场句式和段落节奏。
- 不得出现素材分析、运营目标或创作过程语言。

### 5.2 品类固定结构库

将品类固定结构从“有顺序的结构”改为“无顺序候选内容池”。

例如：

```text
菜品记忆点 -> 可见食材和口感 -> 适合人群 -> 点单建议
```

调整为：

```text
候选内容：菜品记忆点、可见食材和口感、适合人群、点单建议
```

执行要求：

- 固定结构库只在一周计划没有返回有效候选要点时兜底。
- 不再把 `openingOptions` 注入图文草稿 Prompt。
- 内部变量和界面描述优先使用“候选内容”或 `contentCandidates`，避免继续暗示固定顺序。
- `focus` 只表示本篇要解决的问题。
- `avoid` 只保留事实和内容边界，不承担文风控制。
- 历史数据中的箭头内容按并列候选项处理，明确忽略原始顺序，不做数据库迁移。

### 5.3 生成爆款研究任务

OpenClaw 的爆款研究任务调整为两组样本范围。

#### 正文和文风研究

1. 首轮筛选并研究 15-20 篇最近半年内的高点赞图文帖子。
2. 必须归纳至少 5 种有明显差异的正文风格。
3. 每种风格至少由 2 篇不同帖子支撑。
4. 如果首轮样本无法满足要求，继续扩大样本，最多研究 25 篇。
5. 不允许为凑满数量而把高度相似的风格强行拆分。
6. 继续保留作者主页、作者定位和关注量研究，不研究评论区。

#### 图片风格研究

1. 只研究最终入选优先级最高的前 10 篇帖子。
2. 前 10 篇按照内容相关性、发布时间、点赞量和样本代表性综合选择，不能简单截取搜索结果前 10 条。
3. 每篇下载并分析前三张图片，不足三张时分析全部图片。
4. 最多分析 30 张图片。
5. 其余帖子只研究标题、正文和作者，不下载图片。

#### 每种正文风格的输出要求

每种风格必须包含：

- 风格名称
- 适用的内容类型和用户场景
- 叙述者身份或读者感受
- 常见开场方式
- 信息组织和段落节奏
- 句子长短、语言习惯和口语程度
- 情绪浓度和信息密度
- 建议、产品或转化信息的自然植入方式
- 常见结尾和互动方式
- 容易出现的 AI 味、硬广或同质化问题
- 至少 2 个真实案例

每个案例包含：

- 标题
- 作者
- 帖子 URL
- 能够说明该风格的短文本片段
- 该片段体现的具体文风特征

案例短片段只用于说明表达特征，不复制大段正文。

### 5.4 保存并总结爆款研究

沿用当前爆款研究总结链路。第一次 AI 读取账号信息、账号类型配置和 OpenClaw 返回的爆款研究原文；在现有四项字符串总结外，新增一项 `writingStyleInsights`：

```text
summaryMarkdown
contentFeatures
personaInsights
strategyInsights
writingStyleInsights
```

`writingStyleInsights` 是一段直接可读的 Markdown 文本，不使用 `WritingStyle[]` 等嵌套 JSON 数据，也不要求服务端进行结构化校验或 Markdown 渲染。

现有 AI 调用仍可使用 JSON 外壳返回上述五个字符串字段，以兼容当前客户端的解析方式；这里的 JSON 只承担接口传输作用，文风内容本身不是结构化 JSON 数据。

文风总结 Prompt 要求：

- 尽量归纳至少 5 种有明显差异的正文风格；样本不足时明确说明，不强行凑数。
- 每种风格尽量列出至少 2 个来自研究原文的案例。
- 每个案例包含标题、作者、URL、短片段和借鉴点。
- 只摘录足以说明表达特点的短片段，不复制大段正文。
- 不得编造案例、作者、URL 或参考帖事实。
- 总文本控制在合理长度，例如不超过 6,000 个中文字符，避免 `referenceAccounts` 和后续 AI Prompt 过长。

客户端只需做基本非空与长度保护；文风数量、案例数量及真实性由第一次 AI 的 Prompt 约束和研究原文质量保证，不新增服务端校验流程。

保存时，将五项总结拼接进现有账号 `referenceAccounts` 文本：

```markdown
## 人工标记参考账号
...

## 爆款研究总览
{summaryMarkdown}

## 参考账号内容特色
{contentFeatures}

## 人设洞察
{personaInsights}

## 策略洞察
{strategyInsights}

## 爆款正文文风洞察
{writingStyleInsights}
```

### 5.5 爆款增强策划

增强策划时继续读取更新后的 `referenceAccounts` 文本，其中包含独立的“爆款正文文风洞察”章节；第二次 AI 应优先以这五项总结为依据生成策划案，不再只依赖宽泛的 `contentFeatures`。现有流程中传入的研究原文可继续作为事实回查材料，但不应替代总结后的文风洞察。

增强后的完整策划案增加：

```markdown
## 爆款正文文风库

### 风格一：朋友式真实分享
- 适用内容：
- 叙述身份：
- 开场特征：
- 语言节奏：
- 情绪特点：
- 互动方式：
- 避免事项：

#### 参考案例
1. 标题 / 作者 / URL
   - 风格片段：
   - 借鉴点：
```

策划案同时增加文风选择规则：

- 不要求账号全部帖子采用同一种风格。
- 根据单篇内容类型、目标用户和内容目标选择一种主风格。
- 最多选择一种辅助风格，避免多个风格同时混杂。
- 学习表达规律，不复制案例原句、事实和个人经历。
- 商家账号不得伪装成普通消费者亲历。
- 文风案例与账号真实身份冲突时，以账号身份和事实边界为准。

在 `AGENTS.md` 中写入精简版文风库和相同的选择规则，便于 OpenClaw 执行正文任务。

### 5.6 生成图文草稿箱指令

此处对应客户端：

> 笔记草稿 -> 选择一篇笔记 -> 生成图文草稿箱指令

正文任务 Prompt 拆成两个明确区域。

#### 本篇候选内容与事实边界

- 本篇主题和核心观点
- 无顺序候选内容要点
- 图片和账号资料中能够核验的事实
- 不可伪造的信息

Prompt 明确说明：

> 候选内容没有先后顺序，也没有逐项覆盖要求。请根据所选爆款文风、图片内容和读者阅读体验重新组织正文。不得按照候选项原始排列顺序逐条展开。

#### 本篇爆款文风

1. 根据本篇 `contentType`、目标用户、内容目标和账号身份，从 `referenceAccounts` 中的“爆款正文文风洞察”选择一种主风格。
2. 必要时最多选择一种辅助风格。
3. 参考对应案例理解开场、节奏、口语和互动方式。
4. 不输出文风选择和比较过程。
5. 不复制案例原句、个人经历或具体数据。

正文生成顺序：

1. 根据 `topicTitle`、`coreView` 和 `contentGoal` 确定核心主题。
2. 选择最适合的爆款主文风。
3. 读取图片和已知事实。
4. 从候选内容中选择适合本篇的部分。
5. 按所选文风自行决定开场、信息顺序、段落节奏和结尾。
6. 检查是否机械复刻候选项顺序、强行覆盖全部候选项或复制案例表达。

当没有有效爆款文风库时，使用账号对外人设和自然的小红书口语作为兜底，不使用品类固定结构作为文风兜底。

## 6. 前端改动范围

主要文件和职责：

- `src/lib/referenceResearch.ts`
  - 修改 OpenClaw 爆款研究任务。
  - 增加正文文风研究和前 10 篇图片研究限制。
- `src/lib/llm.ts`
  - 扩展爆款研究总结格式，新增 Markdown 字段 `writingStyleInsights`。
  - 将文风洞察和案例写入增强策划及 `AGENTS.md`。
- `src/lib/noteContentStructures.ts`
  - 将固定顺序结构改为无序候选内容。
  - 停止向正文 Prompt 提供固定开场。
- `src/lib/prompt.ts`
  - 拆分候选内容、事实边界和爆款文风。
  - 从 `referenceAccounts` 的“爆款正文文风洞察”章节读取文风信息。
- `src/app/api/accounts/[id]/reference-research/route.ts`
  - 接收并返回 `writingStyleInsights`。
  - 将包含文风洞察的 `referenceAccounts` 传入增强策划。
- `src/app/api/note-tasks/[id]/prompt/route.ts`
  - 将文风库传入图文草稿任务生成。
- `src/app/components/XhsMasterApp.tsx`
  - 补充 `writingStyleInsights` 字段的本地研究记录兼容与展示。
  - 对旧研究显示兼容提示。

## 7. 服务端改动范围

本方案不新增 `writingStyleGuide` 字段，不要求服务端保存结构化文风数据，也不要求服务端渲染 Markdown。

文风洞察会与现有研究摘要一起拼入账号 `referenceAccounts`，再通过现有账号更新接口持久化。因此服务端原则上不需要为本方案新增爆款研究表字段或接口。

唯一需要服务端确认的是：现有 `referenceAccounts` 字段必须能够容纳新增的文风洞察文本，建议使用 `TEXT/LONGTEXT`，避免因字段长度不足而截断。若当前字段长度有限，应扩大该字段容量，而不是新增文风库表。

## 8. 历史数据兼容

- 旧 `bodyStructure` 中的箭头按并列候选项处理，忽略原顺序。
- 旧爆款研究没有“爆款正文文风洞察”章节时继续使用现有 `contentFeatures` 作为低优先级参考。
- 页面提示：当前爆款研究未包含文风洞察，重新执行爆款研究后生效。
- 不从旧摘要中自动伪造 5 种风格和案例。

## 9. 实施顺序

1. 修改爆款研究任务，保证 OpenClaw 能输出足够的正文样本、5 种文风和对应案例。
2. 确认服务端 `referenceAccounts` 字段容量足够保存新增文风洞察。
3. 修改爆款研究总结 AI，增加 `writingStyleInsights` Markdown 输出。
4. 修改爆款增强策划，将文风洞察写入策划案和 `AGENTS.md`。
5. 修改一周计划 AI，将 `bodyStructure` 改为无序候选内容。
6. 修改全品类固定结构库，移除顺序和固定开场影响。
7. 修改图文草稿箱任务 Prompt，由爆款文风决定正文表达。
8. 增加历史数据兼容和页面提示。
9. 完成前后端联调和回归测试。

## 10. 验收标准

### 爆款研究

- 首轮研究 15-20 篇正文，必要时最多扩展到 25 篇。
- 报告至少包含 5 种有明显差异的正文风格。
- 每种风格至少有 2 个不同帖子的案例。
- 图片研究仅覆盖优先级最高的前 10 篇，最多 30 张图片。
- 不研究评论区，不编造作者或帖子数据。

### 爆款增强策划

- 策划案包含完整的“爆款正文文风库”章节。
- 每种文风包含适用范围、表达特征、避免事项和案例。
- `AGENTS.md` 包含可供 OpenClaw 执行的精简文风选择规则。

### 一周计划

- 新生成的 `bodyStructure` 不包含固定顺序。
- 不出现“开头、接着、最后”或箭头式正文流程。
- 候选内容明确标注为可选，不要求全部覆盖。

### 图文草稿

- 同一组候选内容可以根据不同文风形成不同的信息顺序和语言节奏。
- 正文不机械逐项覆盖 `bodyStructure`。
- 正文不出现运营分析、素材说明、AI 身份或内部生成过程。
- 正文能够体现所选爆款文风，但不复制参考案例原句和虚构经历。
- 无爆款文风洞察时仍能使用账号人设正常生成，不因历史数据缺失报错。

## 11. 测试建议

至少选择餐饮、户外和住宿三个品类进行验证：

1. 对每个品类执行一次完整爆款研究。
2. 检查文风数量、案例数量、来源和图片研究数量。
3. 保存研究并增强策划，确认文风库进入策划案和 `AGENTS.md`。
4. 生成一周计划，确认候选内容没有固定顺序。
5. 对同一篇任务分别指定两种不同文风生成正文，比较开场、信息顺序、句式和互动方式。
6. 使用历史账号验证旧 `bodyStructure` 和缺失文风洞察章节的兼容性。
7. 检查正文是否出现参考帖原句、虚假亲历、运营术语或强制覆盖全部候选项。

## 12. 风险与控制

- 样本不足：最多扩展到 25 篇，仍不足时明确报告，不强行凑风格。
- Prompt 过长：正文任务只传入最匹配的主文风及其 2 个案例，必要时附带一个辅助文风，不传完整研究原文。
- 案例抄袭：限制案例片段长度，要求只学习表达规律，并在生成后检查相似表达。
- 商家伪装用户：文风选择不得覆盖账号真实身份和事实边界。
- 图片任务过重：固定只研究前 10 篇、每篇前三张，共不超过 30 张。
- 历史数据缺失：缺少文风洞察章节时提供明确兜底和重新研究提示。
