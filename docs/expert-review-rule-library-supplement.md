# 专家复盘与规则库补充方案

> 状态：待服务端适配后完成客户端联调
> 更新日期：2026-08-02
> 适用项目：`xhs-master-site`、`xhs_server`
> 本文是 `expert-review-ai-refactor-plan.md` 的补充与覆盖说明；若两份文档冲突，以本文为准。

## 1. 目标与边界

专家复盘在站内完成：用户填写单篇帖子证据，后端 AI 返回复盘总结和候选规则，服务端保存复盘记录及规则库。

规则库按“小红书账号”隔离管理：

- 每个账号当前最多保存 15 条规则。
- 每次专家复盘最多生成并提交 5 条规则。
- 每个账号最多启用 5 条规则。
- 未启用规则不参与正文、图片方案或视频方案生成。
- 用户未选择任何规则时，该账号不使用任何规则。
- 不使用置信度字段，也不依据置信度排序或展示规则。

`post_reviews` 保留每一次复盘历史；`expert_rules` 只保存当前账号整理后的规则库，始终不超过 15 条。

## 2. 当前客户端已完成的改动

### 2.1 复盘执行链路

```text
填写单篇复盘信息
-> 执行专家复盘
-> 调用后端 AI 异步任务
-> 解析并校验 JSON 结果
-> 调用服务端 saveResult 保存复盘和候选规则
-> 展示复盘总结与规则库
```

- 移除了复盘 Prompt、复制、下载和手工粘贴规则 JSON。
- “发布表现数据”“评论区 / 私信 / 用户反馈”均为可选。
- 实际发布正文、表现数据、反馈、专家点评、修改对比、主观观察中至少填写一项。
- AI 返回异常时，客户端会尝试从文本、代码块和独立 JSON 对象中提取结果；首次无法解析时，额外进行一次仅修复 JSON 格式的 AI 调用。
- `publishedAt` 会将 `YYYY-MM-DD HH:mm` 自动规范化为服务端接受的 `YYYY-MM-DD HH:mm:ss`。

### 2.2 页面布局

- 左侧：单篇帖子复盘表单。
- 右侧上方：当前笔记最近一次复盘的“复盘总结”。
- 右侧下方：当前账号完整规则库，采用固定最大高度和滚动区域展示。
- “证据评估”仍保存至服务端 `post_reviews`，但不在客户端展示。
- 规则条目展示模块、来源、启用状态、规则内容、依据、适用范围、不适用范围和下次验证方式。

### 2.3 当前生成与消费规则的客户端约束

- 单次复盘 AI Prompt 最多要求 5 条规则。
- 客户端最多向 `saveResult` 提交 5 条规则。
- 正文、图片、视频任务只读取 `enabled === true` 的规则。
- 每次生成最多注入 5 条规则。
- 规则按当前功能相关模块优先、更新时间倒序选择；不再按置信度排序。

## 3. 当前服务端行为与缺口

当前服务端接口 `/client/postReview/v1/saveResult` 能保存复盘和规则，但仍存在以下旧行为：

- 单次最多可保存 50 条规则。
- 新规则默认 `enabled=true`。
- 没有账号级 15 条总量上限。
- 没有精确去重、语义相似合并、归档或删除策略。
- 没有批量修改规则 `enabled` 状态的接口。
- 当前仍接收并返回 `confidence`。

因此，在服务端完成本方案前，客户端不能提供真正可持久化的规则选择界面。不得用浏览器本地状态模拟 `enabled`，否则刷新或换设备后会与服务端不一致。

## 4. 服务端必须完成的需求

### 4.1 数据模型调整

`expert_rules`：

| 字段 | 调整 | 含义 |
|---|---|---|
| `account_id` | 保留 | 所属小红书账号；15 条上限按此字段独立计算 |
| `module` | 保留 | `title`、`cover`、`image_plan`、`video_plan`、`body`、`interaction`、`risk`、`positioning` |
| `rule` | 保留 | 可复用规则文本 |
| `positive_example` 等 | 保留 | 示例、依据、适用范围和验证方式 |
| `enabled` | 保留 | 是否参与后续生成；新规则默认 `false` |
| `confidence` | 删除 | 不再由 AI 或服务端计算、返回、排序或展示 |

`post_reviews`：

- 保留 `summary`、`evidence_assessment`、`input`、`ai_model` 和关联任务等复盘历史。
- `evidence_assessment` 仅供数据保留和未来审计，不要求客户端展示。

建议使用数据库迁移删除 `expert_rules.confidence`；若需要灰度兼容，可先停止读写该字段，后续再删除列。

### 4.2 保存复盘和规则

修改接口：

```text
POST /client/postReview/v1/saveResult
```

请求中规则字段不再包含 `confidence`：

```json
{
  "accountId": 33,
  "noteTaskId": 66,
  "input": {},
  "summary": "单帖复盘总结",
  "evidenceAssessment": "证据评估",
  "aiModel": "gpt-5.5",
  "rules": [
    {
      "module": "body",
      "rule": "每段只保留一个现场观察和一个判断重点。",
      "positiveExample": "...",
      "negativeExample": "...",
      "reason": "...",
      "source": "expert_feedback",
      "applicableWhen": "...",
      "notApplicableWhen": "...",
      "nextTest": "..."
    }
  ]
}
```

保存规则：

- 单次 `rules` 长度必须为 `0-5`。
- 所有新增规则默认 `enabled=false`。
- 复盘记录和规则保存仍保持同一数据库事务。
- 保存完成后返回当前账号最终完整规则库，数量不超过 15 条。
- 服务端必须验证 `accountId`、`noteTaskId`、规则模块和当前用户归属。

### 4.3 同账号 15 条上限与语义合并

规则上限仅针对同一个 `account_id`，不影响同一用户的其他账号。

处理时机：保存本次复盘规则后，如果当前账号规则总数超过 15 条，服务端必须在本次保存流程内完成整理，使 `expert_rules` 最终不超过 15 条。

建议流程：

```text
读取当前账号全部规则 + 本次候选规则
-> 先做同模块精确文本去重
-> 若仍超过 15 条，按 module 分组进行语义相似规则合并
-> 保留差异明显、适用范围不同或互相冲突的规则
-> 删除被合并的旧规则
-> 最终保留不超过 15 条规则
```

语义合并要求：

- 只允许同一 `module` 内合并。
- 不得将适用场景明显不同的规则强行合并。
- 不得将互相冲突的规则强行合并。
- 合并后的规则需要保留更完整的规则文本、依据、适用范围、不适用范围和下次验证方式。
- 若合并来源中存在 `enabled=true`，合并结果继承为 `enabled=true`。
- 合并后仍需保证当前账号 `enabled=true` 的规则最多 5 条。
- 若语义合并依赖 AI，必须校验 AI 返回的模块、来源规则 ID 和最终数量；合并失败时整体保存失败并回滚，不能留下超过 15 条规则的中间状态。

本方案要求 `expert_rules` 表中当前规则本身最多 15 条。被合并规则可从规则表删除；复盘原始证据继续保留在 `post_reviews` 中追溯。

### 4.4 规则选择接口

新增接口：

```text
POST /client/expertRule/v1/setEnabled
```

请求：

```json
{
  "accountId": 33,
  "enabledRuleIds": [201, 205, 208]
}
```

接口规则：

- `enabledRuleIds` 长度必须为 `0-5`。
- 所有规则 ID 必须属于当前用户的当前账号。
- 在同一数据库事务中，先将该账号全部规则设置为 `enabled=false`，再将提交的规则设置为 `enabled=true`。
- 空数组表示该账号全部规则均不启用。
- 响应返回当前账号完整规则库，数量不超过 15 条。

### 4.5 账号详情接口

`POST /client/account/v1/detail` 需要返回：

- 当前账号完整 `expertRules`，最多 15 条。
- 每条规则的 `id`、`module`、`rule`、示例、依据、适用范围、不适用范围、`nextTest`、`source`、`enabled`、更新时间。
- 不再返回 `confidence`。

## 5. 服务端验收标准

1. 同一账号连续多次复盘后，规则表始终不超过 15 条。
2. 不同账号的规则数量彼此独立。
3. 单次提交 6 条规则时返回明确参数错误。
4. 新规则保存后默认 `enabled=false`。
5. 调用 `setEnabled` 后，最多只有 5 条规则为 `enabled=true`。
6. 空 `enabledRuleIds` 能正确关闭该账号全部规则。
7. 规则超过 15 条时，只在同模块中合并语义相近规则。
8. 语义合并失败时不产生部分写入，也不突破 15 条上限。
9. 后续账号详情、正文、图片和视频生成读取的规则状态与 `setEnabled` 返回值一致。
10. 全链路不再读写或展示 `confidence`。

## 6. 服务端完成后的客户端联调项

服务端接口可用后，客户端增加“规则库选择”界面，放在专家复盘右侧规则库区域下方或同一面板内：

- 展示服务端返回的全部规则。
- 每条规则使用复选框控制选择状态。
- 最多允许选择 5 条；达到上限后其他复选框不可选。
- 提供“保存规则选择”按钮，调用 `setEnabled`。
- 用户不选择任何规则时提交空数组。
- 保存成功后直接使用服务端返回的规则列表刷新页面。
- 正文、图片和视频生成继续只读取 `enabled === true` 的最多 5 条规则。
